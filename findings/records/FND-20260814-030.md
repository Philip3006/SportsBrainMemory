# FND-20260814-030 — Consumer does not enforce exact source literals

## Problem / evidence

The Worker requires exact `value` or `manual`, but the consumer uses `(bet.get("source") or "value").strip().lower()`.

Thus missing source defaults to value, uppercase/mixed-case normalizes, and whitespace is silently accepted. The financial ledger boundary does not independently enforce BET-003.

## Failure / impact

Malformed/noncanonical provenance can enter the ledger if the upstream boundary is bypassed or drifts.

## Required closure

Consumer accepts only exact string literals `value` and `manual`; no default, trim or case normalization. Invalid/missing source is permanent REJECT. Add consumer tests for missing, uppercase, mixed-case, whitespace and arbitrary values.
