# FND-20260814-001 — Remote durability can still false-ACK on Git command failure

## Problem / evidence

At `08b63f8a1`, `_durable_push()` adds a remote-containment check, but still ignores the return code of `git add results/ledger_*.csv` and `git fetch origin main`.

Definite false-ACK counterexample:
1. `_append_rows()` writes a new accepted ledger mutation locally.
2. `git add` fails.
3. The failure is ignored.
4. `git diff --cached --quiet` returns 0 because nothing was staged.
5. Existing `HEAD` is already an ancestor of cached `origin/main`.
6. `_durable_push()` returns True.
7. Accepted KV intent is ACKed although the new mutation was never committed/pushed.

`merge-base --is-ancestor` also needs return-code semantics: 0=contained, 1=not contained, >1=verification error.

## Failure / impact

Accepted money-affecting intent can be deleted without durable canonical persistence.

## Required closure

Check every Git operation used as durability proof. `git add` failure and remote `fetch` failure must fail closed. Distinguish merge-base 0/1/error. A failed pull/rebase may not be ignored before push. Add deterministic error-path tests.
