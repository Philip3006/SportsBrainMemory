# FND-20260814-001 — Remote durability still does not fail closed on staged-diff command error

## Verified improvement

At `a90be4c492b736b348dba9b3847c3b1d9823031a`, `_durable_push()` now checks `git add`, `git fetch`, `merge-base` error semantics, pull/rebase failure and push failure. The previous false-ACK path from ignored `git add` is closed.

## Remaining problem / evidence

`git diff --cached --quiet` remains a critical durability-classification command, but its return code is still interpreted as only two states:

- `0` → nothing staged
- any non-zero → assume staged changes and attempt commit

Git uses return `1` for differences, while `>1` is an error. A return `>1` must not be treated as proof that there are staged ledger mutations. TASK-P0A-010 required every Git command used in the durability proof to fail closed.

## Required closure

- `git diff --cached --quiet`: `0` = clean, `1` = staged changes, `>1` = durability verification failure → return False/no ACK.
- Add deterministic rc>1 regression test.
- Preserve the already-correct add/fetch/merge-base/pull/push behavior.
