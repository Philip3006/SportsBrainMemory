# FND-20260814-031 — Recommendation data still auto-downgrades into Manual betting actions

## Verified improvement

A fully legacy `sigCard` lacking canonical identity/status now renders no bet button.

## Remaining problem / evidence

The CEO contract in TASK-P0A-010 was broader: a recommendation that fails canonical Value actionability must not automatically become a Manual betting action from that recommendation surface.

Two bypasses remain at `a90be4c492b736b348dba9b3847c3b1d9823031a`:

1. `sigCard()` still renders a `place-bet-btn-manual` whenever the card has `signal_id + ACTIVE` but `_isValueActionable` is false, e.g. missing `current_odds` / `current_ev_pct`. Thus an incomplete canonical recommendation still automatically downgrades to Manual.
2. `predCard()` / model-tip / all-odds recommendation buttons explicitly set `data-source="manual"` because they have no canonical `signal_id`. The buttons are recommendation-derived and are not a separate user-selected manual-entry flow; the odds buttons are not even visibly labelled as Manual.

This preserves the exact class of alternate recommendation-to-bet path P0-A is intended to remove.

## Required closure

- Any recommendation/model-tip surface without a fully actionable canonical Value signal is informational/non-actionable for bet placement.
- Remove the `sigCard` missing-current-data → Manual fallback.
- Remove/disable direct `predCard` / model-tip recommendation betting buttons that merely relabel noncanonical recommendations as `manual`.
- Do not create a new Manual feature in this task. If a genuinely separate explicit manual-entry UI already exists, it may remain; otherwise temporary absence of Manual betting is safer than recommendation auto-downgrade.
- Update browser tests so missing current odds / legacy / model-tip noncanonical recommendations prove **no bet action**, not forced Manual.
- Preserve canonical actionable Value submit behavior.
